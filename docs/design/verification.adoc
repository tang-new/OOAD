== 明确的跨平台哈希规则

算法始终 SHA-256。源码/配置等明确文本白名单仅执行字节替换 `0D 0A → 0A` 后计算；Java、Python、SQL、YAML、JSON、XML、adoc、图源与 SVG 等文本均按此规则。白名单扩展名/特殊文件名完整列在 index / verification 的 hashRules 中。
不 trim、不去 BOM、不归一化独立 CR、不折叠空白、不更改编码内容。方法体摘要也只归一化 CRLF→LF。除此之外的文件按原始字节，尤其 .class / .jar / .png 不因内部出现 CRLF 就被改写；未知二进制扩展名也保持逐字节。
因此 Windows CRLF 与 Git/CI LF 的同文不会误报；真实代码、方法顺序、二进制字节改变仍失败。这不承诺不同 JDK/编译环境会产生相同 class 字节；二进制确实变化时应重生成并复核，不能以跨平台为由屏蔽。回归测试使用独立临时文件，不修改业务源码或 .gitattributes。旧索引 hashRules 不同必须重新生成，不能混用旧 raw-text 摘要和新规则。
