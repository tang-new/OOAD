= 审查卡模板：由实际审查人填写

本文件为可复制模板，所有结论初始未填写。link:README.adoc[工作包入口]。
将完成的卡片另存为可审阅文档并记录真实提交；不得以生成脚本或本模板替人签字。

[cols="1,4",options="header"]
|===
|字段 |填写内容
|卡片/需求编号 |待填：如ROLE-03/UML-S01；共享测试场景编号与UML编号分开
|主审/互审 |待填：成员、真实审查日期；不能用Git作者自动代填
|源码/合同基线 |待填：完整commit；有未提交修改则记录受影响路径和diff
|状态 |NOT_STARTED / IN_PROGRESS / QUESTION / REVIEWED；有真实运行才填写RUN_VERIFIED
|来源 |原始备注/变更、当前需求、实施合同及OAS；冲突写清裁决依据
|页面/API |HTTP方法、路径、operationId、权限、裸响应/包装、正常与错误码
|structured链 |Controller/DTO→Service具体方法→Mapper/Store→相关表；列真实调用顺序
|DDD链 |REST/Command→Application→Domain行为→Port→Adapter/Entity；列真实调用顺序
|数据与约束 |表/FK/唯一/CHECK；应用负责什么，数据库不能表达什么
|事务/并发 |锁前后读、事务传播、COMMIT、版本/缓存/审计、异常与回滚后的DB预期
|测试证据 |源文件/方法、输入、断言、DB后置条件；仅归档还是本次运行
|图 |两版图名、图源、实际查看PNG、图码差异；无现成图就注明，不能虚构
|GRASP/取舍 |谁掌握信息/谁创建/谁协调、依赖方向、为什么用或不用模式、两范式代价
|CloneFactory |当前真实copy代码、安全排除/显式转换；链路无使用则说明边界，不编造
|问题 |观察到的源码差异、合同依据、未验证假设；本次不自动修复
|互审结论 |伙伴实际独立定位和讲解了什么，尚不能回答什么
|真实提交 |待填：本卡/图文变更对应SHA；无提交则写未提交
|===

== 五分钟讲解结构

. 约30秒：需求、目标身份和场景。
. 约90秒：structured的规则/事务与持久化。
. 约90秒：DDD的对象职责与真实差异。
. 约60秒：异常、测试断言与数据库后置条件。
. 约30秒：图、GRASP与设计代价；接受伙伴追问。

== 测试与完成状态

归档报告：填写原报告路径、执行日期、commit/JAR身份与范围；不改写为本次通过。
本次执行：记录完整命令、环境、退出码、通过/失败/跳过、报告路径；环境失败不当业务RED。
本次仅阅读：填写READ_ONLY，未运行。尚存疑问：填写QUESTION及依据。
真实人工审查完成可以记录REVIEWED；与产品行为RUN_VERIFIED和部署验收分别记账。
