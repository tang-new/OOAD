== 预填调用链：阅读后核对，不代替结论

structured外部：AuthController.write → AuditService.external(trusted/API权限/安全JSON/规范化hash) → 独立事务查重/插入/flush → 事务结束后201；唯一冲突退出后新事务查回。

DDD外部：IdentityController.auditActor → AuditApplicationService.external → 构建AuditFact → fresh事务find/requireReplay或append → 唯一冲突后新事务重读。

本地：业务Service/应用完成环节 → success/local参与同事务；denied独立REQUIRES_NEW；COMMIT在事务代理边界，AOP不是审计权威。

查询：身份/服务来源/API权限 → 当前aud/origin/事件过滤 → SQL过滤排序分页 → 最小Actor和JSON投影。

== 主审检查项

* [ ] requestId唯一不等于先查后插足够；同键同体同id、异体冲突、跨主体/系统不可读他人记录。
* [ ] actor/时间/受控角色快照从可信上下文确定，服务密钥不能替代用户身份或被浏览器持有。
* [ ] 规范化白名单、JSON形态/长度/深度、对象前缀、时间精度和同UUID重试；两版边界差异单列参考。
* [ ] 201必须代表已提交；commit前失败不返回假成功；唯一冲突不能在rollback-only事务里继续假成功。
* [ ] 内外origin和事件过滤、时间闭区间/排序tie-breaker、先授权过滤后分页、deleted与历史快照。
* [ ] 各主审人提供本链路success/denied调用点，F检查公共语义；不假定所有拒绝和409两版都同样记录。
* [ ] 外部课程已提交但HTTP未确认的窗口如实说明，不引入Outbox/MQ或宣称分布式原子性。

== 数据与职责

sys_audit_log，无业务FK、不随用户/角色删除；request_id唯一、payload_hash、origin、系统/操作者/对象时间索引、TIMESTAMP(3)。

迭代复现细则见link:iteration-replay.adoc[复现与Git记录]。轮数/分支/副本/脚本由F决定；各主审人供本链路图和理由，F只协调索引。对A的互审范围限于身份协议、失败计数事务及可信actor，不深审密码学。
